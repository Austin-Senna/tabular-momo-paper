\section{Conclusion}
\label{sec:conclusion}

Tabular agentic QA is an \textbf{execution-discipline problem}, not (only) a retrieval one. Each candidate source represents a multi-turn commitment, and the failure modes that dominate single-agent runs --- schema thrash, zero-row loops, file-handle errors, source drift, premature submit, and context pollution --- all arise from the absence of explicit commitment, scoping, and stopping primitives. Tabular MOMO is a contract-based runtime architecture for this problem: a planner orchestrates without touching raw data tools; bounded search and inspect subagents do the dirty work under explicit contracts; raw schemas and tracebacks remain inside disposable workers; and a partial-success protocol surfaces structured \texttt{missing\_outputs} rather than raw artifacts. MOMO is implemented as a modular extension over a baseline \texttt{DataLakeAgent} via five generic extension hooks, exposing \texttt{results}, \texttt{cot}, \texttt{sprint}, and \texttt{delegation} as separable feature flags. The accompanying harness supports multi-axis ablations over search, planning, computation, and runtime-control settings under shared tasks, budgets, traces, and logs. We position MOMO and the companion SANA ablation framework as complementary: SANA isolates \emph{where} the bottleneck is; MOMO is one structured intervention for the execution-discipline bottleneck that remains after retrieval is idealized.
