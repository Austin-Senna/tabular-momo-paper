We identify a mismatch between text-centric Agentic RAG and exploratory question answering over tabular data lakes. In text QA, retrieval produces directly readable evidence; in tabular QA, retrieval initiates a multi-turn execution commitment that includes schema inspection, file-handle resolution, SQL or code execution, parsing repair, and an explicit stopping decision. The system-level hard problem is not retrieval but \emph{governing multi-turn execution against messy sources}.

We propose \textbf{Tabular MOMO}, a contract-driven runtime control plane that separates planning from bounded data interaction. A planner orchestrates without touching raw data tools; disposable search and inspect subagents perform discovery and source commitment under explicit contracts that declare required outputs, success criteria, evidence schemas, and per-contract budgets. Workers return compact payloads containing answer fragments, enumerated missing outputs, evidence pointers, retry recommendations, and execution statistics. Schema clutter, SQL tracebacks, and row dumps remain inside disposable workers, forming a \emph{context firewall}. Runtime guards enforce file-reference correctness and source-family boundaries as immediate contract violations rather than silent retries.

MOMO is implemented as a modular control-plane extension over a baseline \texttt{DataLakeAgent} harness via five generic extension hooks, leaving the baseline unmodified. We evaluate at the workflow level --- tool waste, context pollution, source-switch churn, partial-success handling, and cost --- not only end-to-end accuracy, and present a failure-mode taxonomy that maps each diagnosed failure mode to the control-plane mechanism that addresses it.
